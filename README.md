# Heirloom

**Bitcoin inheritance, enforced by a contract.**

Millions of BTC are gone for good because their owners died without passing on access. The usual fixes are bad: share your seed phrase (and trust someone with everything today), or hand it to a custodian or lawyer.

Heirloom is a dead man's switch on Stacks. You lock STX in a vault and name an heir. You check in now and then. If you go silent for longer than the period you chose, measured in **Bitcoin blocks**, your heir, and only your heir, can claim the vault. Until then you keep full control.

- **Live app:** https://heirloom-mauve.vercel.app
- **Contract (testnet):** [`ST1B5ADT5PGRQDGZMNEJ7KR4KPD62KSWQPKD371BF.heirloom`](https://explorer.hiro.so/txid/ST1B5ADT5PGRQDGZMNEJ7KR4KPD62KSWQPKD371BF.heirloom?chain=testnet)
- **Built with:** [Scaffold Stacks](https://scaffoldstacks.mintlify.app/) (`stacksdapp` CLI, Clarity 6, Next.js)

## How it works

| Who | Action | Contract function |
|---|---|---|
| Owner | Lock STX, name an heir, pick a period | `create-vault (heir, period, amount)` |
| Owner | "I'm alive": reset the countdown | `check-in` |
| Owner | Add or remove STX (also counts as a check-in) | `deposit`, `withdraw` |
| Owner | Change heir or period (also counts as a check-in) | `set-heir`, `set-period` |
| Heir | Claim after `period` Bitcoin blocks of silence | `claim (owner)` |
| Anyone | Read a vault and its countdown | `get-vault (owner)` |

The countdown uses `burn-block-height`, the height of the Bitcoin chain Stacks settles on. On mainnet a block is about 10 minutes, so one year is about 52,560 blocks. On testnet blocks come every few minutes, so the **Demo** preset (3 blocks) unlocks in about 12 minutes.

Design choices:

- **The owner can always revive.** Missing the deadline does not transfer anything by itself. The heir has to claim, and any owner action before that resets the clock.
- **One vault per owner.** Each vault's balance is tracked separately, and a claim pays out only that vault.
- **No admin.** The deployer has no special powers and no function can move funds except the owner's own withdrawals and the heir's claim.
- **Share a claim link.** The app gives the owner a `/?owner=ST…` link that opens straight into the heir view.

## Run it

Requires Rust, Node 20+, and Clarinet 3.23+ (`stacksdapp doctor` checks everything).

```bash
cargo install stacksdapp          # on Ubuntu first: sudo apt install pkg-config libssl-dev
stacksdapp test                   # 22 contract tests (simnet, no Docker)
stacksdapp dev --network testnet  # app on http://localhost:3000, uses the deployed contract
```

To deploy your own copy, put a funded testnet seed phrase in `contracts/settings/Testnet.toml` (never commit it; the pre-commit hook blocks it) and run `stacksdapp deploy --network testnet --yes`.

Layout:

```
contracts/contracts/heirloom.clar       the contract
contracts/tests/heirloom.test.ts        simnet tests
frontend/src/components/heirloom/       owner + heir UI
frontend/src/lib/heirloom.ts            parsing and formatting helpers
frontend/src/generated/                 hooks generated by `stacksdapp generate`
frontend/src/app/debug/                 generated debug panel for every function
```

## Tests

`contracts/tests/heirloom.test.ts` covers creating and funding a vault, input validation, claims before and after the deadline, claims by non-heirs, double claims, check-ins resetting the clock, partial and full withdrawals, changing heir and period, and isolation between vaults.

The full lifecycle was also run against the live testnet contract: [create-vault](https://explorer.hiro.so/txid/0x3315458f7afa138e1a7ade1ab531f06abeb8a9ab2d9ab44f9a043ba67411b1c2?chain=testnet), then [claim by the heir](https://explorer.hiro.so/txid/0x87c5bc58a15ffb0f6136d890b092a3ea6a485e1dfbcba79195b471ac8c8aac82?chain=testnet) one Bitcoin block later.
